# Ticket Pilot Lab

## ใหม่: ส่วนขยาย 0.2.0 — TTM Reader

เพิ่ม popup ตรวจชื่องาน รอบ และตารางคงเหลือที่มองเห็นในหน้า `https://booking.thaiticketmajor.com/booking/3m/zones.php` หลังผู้ใช้กดตรวจ รองรับการเลือกรอบหนึ่งครั้งเมื่อผู้ใช้กดปุ่มแยก ไม่เลือกที่นั่ง ไม่กรอกจำนวน ไม่จองหรือชำระเงินบน TTM

ใช้สิทธิ์ใหม่ `activeTab` + `scripting` เพื่อเข้าถึงแท็บชั่วคราวเมื่อผู้ใช้เรียกส่วนขยาย ไม่เพิ่ม content script หรือสิทธิ์ host ถาวรบน TTM ไม่มีการอ่านคุกกี้หรือ export query parameters ที่อาจมี token ไม่มีการส่งข้อมูลไปเซิร์ฟเวอร์ของเรา

ต้องอัปเดต/Reload ส่วนขยายก่อนใช้ ดู [คู่มือ TTM Reader](docs/ttm-reader.md) ทดสอบอ่านข้อมูลบนแท็บ TTM จริงใน Chrome รุ่น 0.2.0 สำเร็จแล้วสำหรับงาน Moonshadow Rerun เมื่อ 30 ต.ค. 2569 โดยไม่เปลี่ยนรอบหรือจอง ผลนี้ไม่ครอบคลุมทุกงาน/ระบบคิวหรือการซื้อบัตร

เว็บจองบัตรทดสอบและโปรแกรมผู้ช่วยที่เชื่อมเซิร์ฟเวอร์จริงของโปรเจกต์นี้ ไม่ใช่ภาพจำลองที่เปลี่ยนหน้าตามเวลาอย่างเดียว

**ระบบจองของ Lab ไม่เชื่อม API ซื้อบัตรของ ThaiTicketMajor หรือ AllTicket ไม่มีการชำระเงินจริง ไม่มีการข้ามคิวหรือแก้ CAPTCHA ตัวอ่าน TTM เป็นความสามารถแยกที่ทำงานตามผู้ใช้กดเท่านั้น**

## เปิดใช้งาน

ต้องมี Node.js 22 ขึ้นไป ไม่ต้องสมัครบริการ ไม่ต้องใช้ API key และไม่มี dependencies ที่ต้องติดตั้ง

```sh
npm start
```

เปิด http://127.0.0.1:5208 แล้วกด “เริ่มเข้าคิวและจอง” ค่าเริ่มต้นคือผู้ช่วยหาที่ติดกัน 2 ใบ

ผู้ช่วยจะได้รับสิทธิ์จากคิว อ่านผัง หาที่ติดกัน แล้วขอล็อกจากเซิร์ฟเวอร์ จากนั้นหยุดให้คุณกด “ยืนยันจองทดสอบ” เอง

### ส่วนขยาย Chrome และตัวอย่างแผงลอย

กด **ลองแผงส่วนขยาย · ไม่ต้องติดตั้ง** บนหน้าเว็บ เพื่อทดลอง controller ที่อ่านและคลิกปุ่มบนเว็บ ไม่ต้องสมัครหรือดาวน์โหลดโปรแกรมเพิ่ม ตัว controller ใช้โหมดเลือกเองของหน้าเว็บ แล้วเลือกที่นั่งให้ผ่าน DOM จริง

ส่วนขยาย Chrome อยู่ใน `extension/` ใช้โค้ด controller เดียวกับตัวอย่าง แต่ต้องติดตั้งแบบ Load unpacked เอง ดู [คู่มือส่วนขยาย](extension/README.md) ตัวอย่างในหน้าเว็บไม่ใช่การติดตั้ง extension ใน Chrome และไม่เชื่อมเว็บขายตั๋วอื่น

### โปรแกรมผู้ช่วยแยกจากหน้าเว็บ

เปิด Terminal อีกหน้าต่างในโฟลเดอร์นี้ ขณะเซิร์ฟเวอร์กำลังรัน:

```sh
npm run assistant
```

จะทดสอบเข้าคิวและล็อกคู่ที่ติดกันแล้วปล่อยกลับ ถ้าต้องการให้จบด้วยการสร้างรายการทดสอบ:

```sh
npm run assistant -- --confirm
```

โปรแกรมใน `assistant.mjs` เชื่อมเฉพาะ `127.0.0.1` ของสนามทดสอบ ไม่รับ target URL ภายนอก กด Ctrl+C เพื่อออกจากคิวและปล่อยที่นั่ง หากใช้พอร์ตอื่นให้ตั้ง `LAB_PORT` ให้ตรงกับ `PORT` ของเซิร์ฟเวอร์

## วิธีทดสอบสองคน

1. ในหน้าหลัก กด “เปิดผู้ซื้อทดสอบอีกคน” จะได้เซสชันอีกคนในแท็บใหม่
2. ตั้งทั้งสองหน้าต่างเป็น “เลือกที่นั่งเอง” เลือกรอบและโซนเดียวกัน แล้วเริ่มเข้าคิว
3. เลือก B4 กับ B5 ในสองหน้าต่างก่อนล็อก แล้วกดล็อกไล่กัน ระบบต้องยอมรับผู้ชนะเพียงคนเดียว อีกคนเห็นข้อขัดแย้งและผังล่าสุด
4. ถ้าไม่ยืนยันภายใน 45 วินาที ที่นั่งจะคืนให้คนอื่น ลองรอแล้วเลือกใหม่
5. เปิดผู้ซื้อคนที่สามขณะสองคนแรกยังอยู่ในหน้าซื้อ คนที่สามจะต้องรอคิว จนมีคนออก ยืนยันรายการ หรือสิทธิ์หมดอายุ

โซนสำรองทำงานเมื่อโซนหลักไม่มีที่ติดกัน หรือเมื่ออีกคนล็อกที่นั่งตัดหน้าระหว่างอ่านผังกับขอล็อก ผู้ช่วยตรวจเพียงสองโซนที่คุณตั้งไว้ ไม่ยิงคำขอซื้อแบบไม่จำกัด

## สิ่งที่มี

- คิว FIFO ที่เซิร์ฟเวอร์อนุญาตครั้งละ 2 คน หลังเริ่มเซิร์ฟเวอร์ 3 วินาที
- สิทธิ์เข้าซื้อ 120 วินาที และการล็อกที่นั่ง 45 วินาที
- รอบ A/B, โซน LA2/RA2 ราคา 3,200 บาท และ LB2/RB2 ราคา 2,600 บาท (ข้อมูลสมมติ)
- ล็อกที่นั่งทั้งกลุ่มพร้อมกัน ถ้าบางที่ไม่ว่างจะไม่ล็อกบางส่วน
- ตรวจเจ้าของการล็อกก่อนอ่าน/ปล่อย/ยืนยัน
- ยืนยันรายการซ้ำด้วย hold เดิมจะคืนรายการเดิม ไม่สร้างรายการซื้อซ้ำ
- บันทึก HTTP requests บนหน้าจอ เปิดผู้ซื้อหลายคนเพื่อทดสอบได้
- UI ภาษาไทย ใช้ได้บนหน้าจอเล็ก ไม่มีข้อมูลบัตรประชาชนหรือบัตรเครดิต

## ใช้กับ GitHub อย่างไร

GitHub เก็บ source code และเชื่อม frontend กับ backend ผ่านโค้ดใน repository นี้ได้ แต่การเรียก API เกิดที่เซิร์ฟเวอร์ Node.js ของคุณ ไม่ได้เกิดเพียงเพราะเอาไฟล์ขึ้น GitHub

1. สร้าง repository เปล่าในบัญชีของคุณ (เริ่มแบบ private ได้)
2. เปิด Terminal ในโฟลเดอร์นี้ แล้วใช้คำสั่งใน [docs/github.md](docs/github.md)
3. ไฟล์ `.github/workflows/test.yml` จะรัน tests เมื่อ push หรือเปิด pull request
4. รันด้วย `npm start` บนเครื่อง หรือใช้ GitHub Codespaces ตามคู่มือ

**GitHub Pages อย่างเดียวรันระบบนี้ไม่ได้** เพราะเป็น static hosting ส่วนระบบคิว/ล็อกที่นั่งต้องใช้ backend

ไม่มีการอัปโหลดหรือสร้าง repository ให้โดยอัตโนมัติในเวอร์ชันนี้

## ขอบเขตทางเทคนิค

- ข้อมูลอยู่ใน RAM รีสตาร์ตแล้วคิว ที่นั่ง และรายการเริ่มใหม่
- รองรับ **หนึ่ง Node.js process เท่านั้น** การตรวจและล็อกเป็น synchronous ใน process เดียว หากขยายหลาย process ต้องเปลี่ยนเป็น database transaction/unique constraint หรือกลไก atomic ร่วมกันก่อน
- ใช้ได้สำหรับห้องทดลอง ไม่มีระบบสมาชิกและ payment provider สำหรับขายบัตรจริง
- ค่าเริ่มต้นฟังเฉพาะ `127.0.0.1` ถ้าทดสอบผ่าน Codespaces ให้ `HOST=0.0.0.0 npm start` และตั้ง forwarded port เป็น Private
- คิวไม่ใช่ระบบจำลองของ TTM/AllTicket และเวลาหรือผลลัพธ์ไม่สะท้อนวันขายจริง
- token เป็น session ทดสอบ เก็บใน sessionStorage ของแท็บ อย่าใช้ credential หรือข้อมูลส่วนตัวจริง
- เลือกข้อมูลเท่าที่ต้องใช้: ไม่มีการดาวน์โหลดข้อมูลหรือส่ง request ไปยังเว็บขายบัตรอื่น

## โครงสร้าง

```text
booking.mjs          กฎคิว ที่นั่ง การล็อก และรายการจอง
server.mjs           HTTP server + API + static UI
assistant.mjs        โปรแกรมผู้ช่วยแยก process ที่เชื่อม localhost lab
public/              หน้าจอและผู้ช่วยที่เรียก API ใน origin เดียวกัน
test/                automated tests รวมการแย่งที่นั่งผ่าน HTTP
.github/workflows/   CI บน GitHub
docs/                คู่มือ API และ GitHub
```
